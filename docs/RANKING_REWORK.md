# Ranking and movement follow-up

Plan: replace implicit name-based load scaling with a catalogue-wide model that
states the movement reference, load convention, unilateral status and any reason
it cannot be ranked. Score matched left/right working sets using the weaker
side; a 30 kg × 8 pair on a single-arm plate-loaded machine must match 60 kg × 8
bilaterally. Dumbbell entries use weight per dumbbell; shared implements use
total external weight. Warm-ups, incomplete pairs, timed sets and unsupported
measurements must not inflate strength rank.

Keep the existing tier/division boundaries and server score contract. Recompute
derived scores from unchanged logs; never rewrite identities, routines, records
or user-entered weights. These remain app game references, not machine-independent
population standards. Document every catalogue model and its limitations.

Extend reviewed side pairs, then present genuinely single-side-only movements
under a neutral movement label with their fixed execution retained. Do not invent
two-arm versions of moves that cannot be done that way. Search original names
and aliases; keep concrete identities in routines and history.

Allow crunches to contribute to abs and obliques, and rows to mid-back and traps,
without adding duplicate terms to overall rank. Simplify the rank explanation,
picker helper copy and bodygraph shapes; keep necessary input units and the
real-account preview notice. Validate catalogue coverage, side-pair equivalence,
uneven/incomplete sides, histories, save/reopen, offline use and anatomy.

This stays on draft PR38 and the existing private preview. Public preview access
is still awaiting explicit approval; no official release or long CI wait.

## Implemented and validated

All 1,033 catalogue identities have a rule in [RANK_MODELS.csv](RANK_MODELS.csv),
regenerated by `node tools/rank-audit.mjs`: 688 support load-based ranks and 345
have an explicit exclusion reason. These are game benchmarks, often shared by
movement/muscle group, not individually validated standards for every machine.
Custom lifts retain ranking from the muscle/side settings the user selected.

One-rep sets use actual load; 2–12 reps use Epley. Dumbbell inputs are per dumbbell;
shared goblet/overhead implements use total load. One-side inputs normalize to
twice the load. L/R working pairs use the weaker equivalent estimate: 30 kg × 8
on each arm equals 60 kg × 8 bilateral, not 60 kg × 16. Incomplete pairs and
warm-ups do not earn strength rank. Raw weights, volume and records remain as
logged. Score is floor(300 × equivalent e1RM / bodyweight / reference), bounded
0–999. Tier/division boundaries and the integer server score contract are retained.
Primary muscle bests are averaged once; regional row/crunch contributions do
not duplicate overall-rank terms. Upright-row models now agree on Shoulders.

New unilateral logs retain an optional execution flag and blank row positions
through save/sanitize/merge. History is not migrated. Old logs without metadata
use the catalogue convention; positions removed by old clients cannot be
recovered. Old clients may omit new metadata when editing and submit old-model
shared scores until updated; no database schema/access policy changes are made.

There are now 44 reviewed side pairs within 117 presentation families: 985 picker
results retain all 1,033 identities. Fixed one-side moves get neutral labels;
no impossible bilateral variants are invented. Calculator choices use the same
families and explicit input units. Saved routine/history names stay concrete.

Brachialis fills the biceps/elbow gaps without cutting the original biceps.
Posterior spine edges meet at a fine seam; inner hamstrings end above the knee.
Original calves and saved appearance are retained. Rank/picker explanations
were shortened; necessary units and the shared-account notice remain.

Lint and 161 unit tests passed. Sixteen distinct focused browser cases passed,
including equal side scores, calculator units, incomplete-side save/reopen,
existing logging, warm-ups, timed history and themes. Final calculator/save cases
passed again after refinements. A genuine service-worker offline reload verified
the new cached model, neutral search, side equivalence and byte-identical canonical
logs/routines. Magnified front/back and phone views were inspected. No production
account was used for tests. Full remote CI and native checks remain pending.
